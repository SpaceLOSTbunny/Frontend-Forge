Learn HTML

HTML is the skeleton of every website — the tags that give your content structure and meaning. Work through the lessons below, then head to the Practice Zone to test what you've learned.

1. Structure 2. Text & Headings 3. Links & Images 4. Lists & Tables 5. Forms 6. Semantic HTML5 7. Forms Deep Dive 8. Attributes & Meta 9. Accessibility 10. Tables Deep Dive 11. iframes & Embeds 12. Canvas & SVG 13. Web Storage 14. Responsive Images 15. Web Components
Lesson 1

Document Structure

Every HTML page starts with the same skeleton: a <!DOCTYPE html> declaration, an <html> root element, a <head> for metadata the browser needs (but doesn't display), and a <body> that holds everything visitors actually see.

<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <title>My First Page</title> </head> <body> <h1>Hello, world!</h1> </body> </html>

The lang attribute helps screen readers and translators, and <meta charset="UTF-8"> tells the browser how to decode the text on the page.

Lesson 2

Text & Headings

Headings (<h1> through <h6>) create a hierarchy of importance, and <p> holds paragraphs of text. Inline tags like <strong> and <em> add meaning, not just style.

<h1>Frontend Forge</h1> <h2>Why Learn HTML?</h2> <p> HTML is <strong>essential</strong> for every website — it's the <em>first</em> language every web developer learns. </p>

Only use one <h1> per page — it should describe what the whole page is about, with <h2>–<h6> nesting beneath it for sections and subsections.

Lesson 3

Links & Images

The anchor tag <a> creates a hyperlink using the href attribute. The <img> tag embeds an image and is self-closing — it always needs a src and, for accessibility, an alt description.

<a href="https://example.com" target="_blank"> Visit Example.com </a> <img src="forge-logo.png" alt="Frontend Forge logo">

target="_blank" opens a link in a new tab. The alt text is read aloud by screen readers and shown if the image fails to load — never leave it empty on a meaningful image.

Lesson 4

Lists & Tables

Use <ul> for an unordered (bulleted) list or <ol> for an ordered (numbered) one, with each item wrapped in <li>. Tables use <table>, <tr> for rows, and <td> for cells.

<ul> <li>HTML</li> <li>CSS</li> <li>JavaScript</li> </ul> <table> <tr><th>Language</th><th>Role</th></tr> <tr><td>HTML</td><td>Structure</td></tr> </table>

<th> defines a header cell — browsers bold and center it by default, and it helps screen readers announce column meaning.

Lesson 5

Forms & Inputs

Forms collect user input. The <form> element wraps controls like <input>, <textarea>, and <button>. Always pair an input with a <label> so it's clear what the field is for.

<form action="/submit" method="POST"> <label for="email">Email</label> <input type="email" id="email" required> <button type="submit">Subscribe</button> </form>

Input type matters: email, date, and number all give mobile users a tailored keyboard, and required triggers built-in browser validation.

Lesson 6

Semantic HTML5 & Media

Semantic tags like <header>, <nav>, <main>, <section>, <article>, and <footer> describe the role of content instead of just its layout — better for accessibility and SEO than a page built entirely from generic <div>s.

<header><h1>My Blog</h1></header> <main> <article> <h2>Post Title</h2> <p>Post content goes here...</p> </article> </main> <footer><p>&copy; 2026</p></footer> <video src="clip.mp4" controls></video>

The <video> and <audio> tags embed media natively — no plugins needed — and the controls attribute adds a built-in play bar.

Lesson 7

Forms Deep Dive

Beyond a text <input>, forms have controls purpose-built for different choices: <select> for a dropdown, radio buttons for picking exactly one option from a group, checkboxes for independent on/off toggles, and <textarea> for multi-line text.

<fieldset> <legend>Choose a plan</legend> <label><input type="radio" name="plan" value="free"> Free</label> <label><input type="radio" name="plan" value="pro" checked> Pro</label> <label><input type="checkbox" name="updates"> Email me updates</label> <select name="role"> <option value="dev">Developer</option> <option value="designer">Designer</option> </select> <textarea rows="3" placeholder="Anything else?"></textarea> </fieldset>

Radio buttons sharing the same name act as a single group — selecting one clears the others — while checkboxes are always independent. <fieldset> and <legend> group related controls and give assistive tech a label for the whole group, not just one field.

Lesson 8

Attributes, Data Attributes & Meta Tags

Attributes add information to a tag without changing what's shown on the page. Alongside standard ones like class and id, a data-* attribute lets you attach custom information of your own that JavaScript can read back later.

<button data-course="css" data-difficulty="beginner"> Start CSS </button> <script> const btn = document.querySelector('button'); console.log(btn.dataset.course); // "css" </script>

Every data-* attribute is automatically readable through an element's dataset property — data-course becomes dataset.course. This is exactly how Frontend Forge itself remembers which course card you clicked. <meta> tags work similarly for the whole page: a description meta tag summarizes it for search engines, and <link rel="icon"> sets the little tab favicon.

Lesson 9

Accessibility Basics

Accessible HTML means anyone — including someone using a screen reader or navigating by keyboard only — can understand and use your page. Most of it comes down to giving elements the right names and roles.

<button aria-label="Close menu">✕</button> <nav aria-label="Main"> ... </nav> <img src="chart.png" alt=""> <!-- empty alt = purely decorative, screen readers skip it --> <span aria-hidden="true">🔥</span> Dedicated Learner

aria-label gives assistive tech a name for a control when there's no visible text, like an icon-only close button. An empty alt="" marks an image as decorative so screen readers skip it, and aria-hidden="true" does the same for any element — it's why the drifting embers behind this page and the badge icons are marked hidden, so they don't get read aloud as noise.

Lesson 10

Tables Deep Dive

A real table is more than rows of <td>. <thead>, <tbody>, and <tfoot> group a table into a header, body, and footer, which browsers can style and scroll independently. colspan and rowspan let a single cell stretch across multiple columns or rows.

<table> <thead> <tr><th>Course</th><th>Lessons</th><th>Level</th></tr> </thead> <tbody> <tr> <td colspan="2">HTML & CSS Basics</td> <td>Beginner</td> </tr> <tr><td>JavaScript</td><td>12</td><td>Intermediate</td></tr> </tbody> </table>

<th scope="col"> also tells screen readers which column or row a header describes — add scope="col" or scope="row" for anything more complex than a simple grid.

Lesson 11

iframes & Embedded Content

An <iframe> embeds another entire HTML document inside the current page — a map, a video, a payment widget. It behaves like a little browser window nested in yours, with its own scripts and styles that can't reach the parent page directly.

<iframe src="https://example.com/widget" title="Embedded pricing widget" width="100%" height="400" loading="lazy"> </iframe>

Always give an iframe a title — screen readers announce it so users know what the embedded frame is for. loading="lazy" defers loading the frame until it's about to scroll into view, which keeps the initial page load fast.

Lesson 12

HTML5 Canvas & SVG

HTML has two built-in ways to draw graphics without an image file. <canvas> is a blank pixel surface you draw on with JavaScript — great for games, charts, and effects like this site's drifting-ember background. <svg> describes shapes declaratively as markup, so they stay crisp at any zoom level and can be styled with CSS.

<svg viewBox="0 0 100 100" width="100" height="100"> <circle cx="50" cy="50" r="40" fill="#ff6b35"/> <rect x="20" y="20" width="24" height="24" fill="#ffb627"/> </svg>

Rule of thumb: reach for SVG for icons, logos, and diagrams (like the ones throughout this course) where crispness and CSS styling matter; reach for canvas when you need to redraw thousands of pixels quickly, like an animation or a game loop.

Lesson 13

Web Storage: localStorage & sessionStorage

The browser can hold onto small pieces of data between visits without a server at all. localStorage persists until it's explicitly cleared; sessionStorage disappears the moment the tab closes. Both only store strings, so objects need JSON.stringify/JSON.parse to round-trip.

<script> localStorage.setItem('forge_theme', 'dark'); const theme = localStorage.getItem('forge_theme'); const progress = { html: true, css: false }; localStorage.setItem('progress', JSON.stringify(progress)); const restored = JSON.parse(localStorage.getItem('progress')); </script>

Both APIs are synchronous and roughly 5–10MB per origin — fine for settings and progress, but not for large files. For anything bigger or shared across devices, that data needs to live on a server instead.

Lesson 14

Responsive Images

A single <img> forces every visitor to download the same file, whether they're on a phone or a 4K monitor. srcset and sizes let the browser pick the best-fitting image itself, and <picture> can swap the format or crop entirely at different breakpoints.

<img src="hero-800.jpg" srcset="hero-400.jpg 400w, hero-800.jpg 800w, hero-1600.jpg 1600w" sizes="(max-width: 600px) 100vw, 50vw" alt="Forge workshop banner"> <picture> <source srcset="hero.avif" type="image/avif"> <source srcset="hero.webp" type="image/webp"> <img src="hero.jpg" alt="Forge workshop banner"> </picture>

The browser reads each candidate's width (400w) alongside sizes to work out how many CSS pixels the image will actually occupy, then downloads only the smallest file that's still sharp enough — saving bandwidth on mobile without any JavaScript.

Lesson 15

Templates & Web Components

The <template> tag holds markup that the browser parses but never renders or runs — it's inert until JavaScript clones it into the page. Combined with custom elements, this is the foundation of native Web Components, framework-free reusable widgets.

<template id="badge-template"> <div class="badge"> <span class="badge-icon"></span> <span class="badge-name"></span> </div> </template> <script> const tpl = document.getElementById('badge-template'); const clone = tpl.content.cloneNode(true); clone.querySelector('.badge-name').textContent = 'Dedicated Learner'; document.body.appendChild(clone); </script>

A custom element like <forge-badge> can wrap this pattern into its own tag using customElements.define(), giving you a reusable component with no build tools or frameworks required.

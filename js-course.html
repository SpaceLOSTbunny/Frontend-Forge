Learn JavaScript

JavaScript brings a page to life — it reacts to clicks, updates content, and talks to servers. Work through the lessons below, then head to the Practice Zone to test what you've learned.

Lesson 1

Variables & Data Types

Modern JavaScript uses let for values that change and const for values that don't — prefer const by default. The core data types are strings, numbers, booleans, arrays, objects, and null/undefined.

const name = "Ada"; // string let score = 95; // number const isActive = true; // boolean let user = null; // explicitly empty console.log(typeof score); // "number"

Avoid the older var keyword — let and const are scoped to the block they're declared in, which avoids a whole class of bugs.

Lesson 2

Functions & Conditionals

Functions package up reusable logic. Arrow functions (=>) are a compact modern syntax. if/else branches let code make decisions based on a condition.

function greet(user) { if (user) { return `Hello, ${user}!`; } else { return "Hello, stranger!"; } } const double = n => n * 2; console.log(greet("Ada")); // "Hello, Ada!"

Template literals — strings wrapped in backticks — let you embed variables directly inside ${} placeholders instead of clunky string concatenation.

Lesson 3

Arrays & Loops

Arrays hold ordered lists of values. Rather than manual for loops, modern JS favors array methods like map(), filter(), and forEach() for transforming and iterating over data.

const nums = [1, 2, 3, 4, 5]; const doubled = nums.map(n => n * 2); const evens = nums.filter(n => n % 2 === 0); nums.forEach(n => console.log(n)); // doubled -> [2, 4, 6, 8, 10] // evens -> [2, 4]

map() always returns a new array the same length as the original; filter() returns a new array with only the items that pass a test.

Lesson 4

The DOM

The DOM (Document Object Model) is how JavaScript sees and changes the page. document.querySelector() finds an element using a CSS-style selector, and you can then read or update its content and attributes.

const heading = document.querySelector('h1'); heading.textContent = "Updated title!"; const cards = document.querySelectorAll('.card'); cards.forEach(card => card.classList.add('visible'));

Use textContent to safely set plain text — avoid innerHTML with any data you didn't write yourself, since it can open the door to injection attacks.

Lesson 5

Events

addEventListener() runs a function whenever something happens — a click, a keypress, a form submission. It's the bridge between user actions and your code.

const btn = document.querySelector('#saveBtn'); btn.addEventListener('click', () => { console.log('Saved!'); }); form.addEventListener('submit', (e) => { e.preventDefault(); // stop the page from reloading });

e.preventDefault() is essential on form submissions when you want to handle the data with JavaScript instead of letting the browser do a full page reload.

Lesson 6

Objects & JSON

Objects group related data as key-value pairs. JSON (JavaScript Object Notation) is the text format used to send that data across the web — JSON.stringify() and JSON.parse() convert between the two.

const user = { name: "Ada", role: "developer" }; const json = JSON.stringify(user); // '{"name":"Ada","role":"developer"}' const parsed = JSON.parse(json); console.log(parsed.name); // "Ada"

This same pattern powers localStorage — since it only stores strings, objects are stringify'd before saving and parse'd back after reading.

Lesson 7

Async JavaScript & Fetch

Some operations — reading a file, waiting on a network request — take time and shouldn't freeze the page while they run. A Promise represents a value that will exist eventually, and async/await is the modern, readable way to work with one.

async function loadUser() { try { const res = await fetch('/api/user'); const data = await res.json(); console.log(data.name); } catch (err) { console.error('Failed to load:', err.message); } }

await pauses a function until its Promise settles, so asynchronous code reads top-to-bottom like ordinary code instead of nesting callbacks inside callbacks. Always wrap it in try/catch — a dropped connection or a bad response will throw, and an uncaught error in an async function otherwise fails silently.

Lesson 8

Error Handling

try/catch lets your code fail gracefully instead of crashing the whole page. throw stops execution and hands an error to the nearest catch; an optional finally block always runs afterward, whether or not an error happened.

function divide(a, b) { if (b === 0) throw new Error('Cannot divide by zero'); return a / b; } try { console.log(divide(10, 0)); } catch (err) { console.error(err.message); } finally { console.log('Done attempting the division.'); }

This exact pattern is what keeps a typo in the Playground above from crashing the whole page — your code runs inside a try/catch, and any error gets caught and printed to the console panel instead of breaking the preview.

Lesson 9

ES6+ Features: Destructuring & Spread

Destructuring unpacks values out of an object or array into their own variables in a single line. The spread operator (...) does the reverse — it expands an array or object's contents, which is perfect for merging data or copying it without mutating the original.

const user = { name: 'Ada', role: 'developer' }; const { name, role } = user; // destructuring const nums = [1, 2, 3]; const [first, ...rest] = nums; // rest -> [2, 3] const merged = { ...user, active: true }; // spread

You'll see this exact spread pattern all over Frontend Forge's own code — merging a saved progress object with sensible defaults, or copying a quiz question while adding a topic field, all without ever mutating the original data.

Lesson 10

The Event Loop

JavaScript runs on a single thread, yet setTimeout, DOM events, and fetch all seem to happen "in the background." The trick is the event loop: slow work is handed off to browser Web APIs, and only its callback comes back — waiting in a queue until the call stack is completely empty.

console.log('1: start'); setTimeout(() => console.log('2: timeout callback'), 0); console.log('3: end'); // Logs in order: 1, 3, 2 — even with a 0ms delay, // the timeout callback waits for the stack to clear first.

This is exactly why a 0ms setTimeout never runs immediately — it still has to wait its turn behind whatever synchronous code is currently running.

Lesson 11

Array Methods Deep Dive: reduce() & sort()

reduce() is the most general array method — it walks through every item, combining it with an accumulator, and returns one final value. sort() reorders an array in place; without a compare function it sorts alphabetically, even for numbers, which is a classic bug.

const scores = [10, 25, 15, 30]; const total = scores.reduce((sum, n) => sum + n, 0); // sum starts at 0, then adds each score in turn const sorted = [...scores].sort((a, b) => a - b); // (a, b) => a - b sorts numerically, ascending console.log(total, sorted); // 80 [10, 15, 25, 30]
Lesson 12

Closures & Scope

A function remembers the variables that were in scope where it was defined, not where it's called — that's a closure. It's how a counter function can keep its own private count between calls without any global variable.

function makeCounter() { let count = 0; // lives in makeCounter's scope return function () { count++; // inner function "closes over" count return count; }; } const counter = makeCounter(); counter(); // 1 counter(); // 2 — count persisted between calls

This is precisely how the Playground's own state stays isolated — each editor instance is wrapped in a function whose closed-over variables no other part of the page can reach or accidentally overwrite.

Lesson 13

Classes & OOP

A class is a template for creating objects that share the same methods. constructor runs when you write new ClassName(...), and extends lets one class inherit and override behavior from another — the same pattern behind almost every UI framework's components.

class Course { constructor(name, lessons) { this.name = name; this.lessons = lessons; this.completed = 0; } progress() { return Math.round((this.completed / this.lessons) * 100); } } class CertifiedCourse extends Course { constructor(name, lessons) { super(name, lessons); // call the parent constructor this.certified = false; } } const html = new CertifiedCourse('HTML', 15); html.completed = 9; html.progress(); // 60

Under the hood, classes are still JavaScript's regular prototype chain with friendlier syntax — html.progress() works because JavaScript walks up from the instance to CertifiedCourse.prototype to Course.prototype looking for the method.

Lesson 14

Modules: import & export

ES modules split code across files instead of one giant script. Each file has its own scope by default — nothing leaks into the global namespace — and you explicitly choose what to export and what to import elsewhere.

// progress.js export const STORAGE_KEY = 'forge_progress'; export function loadProgress() { return JSON.parse(localStorage.getItem(STORAGE_KEY)) || {}; } export default class ProgressTracker { /* ... */ } // main.js import ProgressTracker, { loadProgress, STORAGE_KEY } from './progress.js'; <script type="module" src="main.js"></script>

A default export is imported without curly braces and can be renamed freely; named exports ({ loadProgress }) must match the exported name unless you use as. The browser needs type="module" on the <script> tag to enable this syntax at all.

Lesson 15

Web Storage & JSON in JavaScript

JSON.stringify() turns a JavaScript object into a text string that can be saved to localStorage, sent over the network, or logged; JSON.parse() reverses it. Together they're how any structured data survives a page reload.

function saveProgress(state) { localStorage.setItem('forge_progress', JSON.stringify(state)); } function loadProgress() { const raw = localStorage.getItem('forge_progress'); return raw ? JSON.parse(raw) : { courses: {}, quizBest: 0 }; } const state = loadProgress(); state.quizBest = Math.max(state.quizBest, 92); saveProgress(state);

Functions, undefined, and circular references can't survive JSON.stringify — they're silently dropped or throw. Wrap JSON.parse in a try/catch too, since corrupted or hand-edited storage will throw a SyntaxError rather than fail quietly.
